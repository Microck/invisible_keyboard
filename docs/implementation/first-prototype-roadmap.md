# First passive-surface prototype: implementation and execution roadmap

Date: 2026-08-12
Latest dated remote evidence: 2026-09-07

## The answer in one minute

Build one wired hand first with this exact topology:

- one Seeed Studio XIAO nRF52840 Plus controller;
- one Adafruit TCA9548A I2C multiplexer;
- six identical Adafruit LSM6DS3TR-C IMU breakouts;
- one IMU on each finger and one on the dorsal hand; and
- six direct data-ready lines plus per-sensor timestamps.

The selected active boards cost USD 77.05 for one hand before harness, mounts,
shipping, tax, and a spare. The exact Rev-A harness uses five full wire spools,
so a realistic one-hand planning envelope is USD 227. A realistic two-hand
wired envelope is USD 399 because the second hand reuses the wire stock. No
item has been bought or reserved.

The surface remains passive and unmarked. A normal keyboard is used only during
guided calibration as a non-admission signal precheck. Disjoint passive-surface
centroid, threshold-selection, and held-out blocks decide the saved validation
result. Live output then requires a fresh per-process user attestation that
both wearables have not moved.

The software, SensorFrame-v2 wire protocol, IKS3 session recorder, portable
firmware boundary, deterministic Gate 0A quiesce path, baseline decoder, causal
segmenter, fault-safe key output, simulation, and tests exist in this
repository and build with Bazel. The unresolved fact is physical: nobody can
establish from code or papers alone that six wearable IMUs can distinguish all
same-finger Core-28 keys across remounts and ordinary motion.

The plan therefore spends the first hardware money on a one-hand falsification
rig. It does not polish BLE, batteries, custom PCBs, or a consumer enclosure
before key evidence exists.

## Evidence labels

Every conclusion below uses one of these labels:

- **Source-verified:** established by an inspected source, schematic, or
  datasheet.
- **Statically verified:** established by code inspection or arithmetic without
  physical hardware.
- **Replay-tested:** executed through recorded or generated byte/session input.
- **Simulated:** true only inside the explicit deterministic signal model.
- **Hardware-dependent:** requires the selected physical rig and measurement.

Remote build and test records are dated validation records, not a sixth evidence
class. Do not combine these labels. A simulated key score is not evidence that
a real finger produces the assumed signal.

## Product boundary

The first product claim is personal, calibrated, exact Core-28 tap entry on an
ordinary rigid surface:

- A-Z
- Space
- Backspace

Six additional physical positions remain reserved: Semicolon, Comma, Period,
Slash, left outer thumb, and right outer thumb. A reserved classification emits
no key.

Core-28 is the enabled output set on a 34-position physical grid. Its rows are
US-QWERTY-shaped, but this project defines finger ownership: `B` belongs to the
left index finger, Backspace to the left functional thumb, and Space to the
right functional thumb. The two outer thumbs are reserved. Do not treat those
assignments as a fact supplied by LapCal or by generic QWERTY convention.

Core-28 has no hold, modifier, repeat, chord, or rollover semantics. Those
features require later gates. The first target is seated two-hand use on one
desk, with a complete remount treated as a new session. "Type anywhere" becomes
a product claim only after held-out surfaces, postures, remounts, and ordinary
movement pass their gates.

The regular keyboard used for warm-start calibration is setup equipment. It is
not present during invisible typing. Details are in the
[guided calibration contract](calibration-experience.md).

## Selected one-hand hardware

### Architecture

```text
                        direct GPIO data-ready lines
          +---------------------------------------------------+
          |          |          |         |         |         |
          v          v          v         v         v         v
       thumb       index      middle     ring      pinky     dorsal
       IMU ch0     IMU ch1    IMU ch2   IMU ch3   IMU ch4    IMU ch5
          |          |          |         |         |         |
          +----------+----------+---------+---------+---------+
                      separately selected I2C branches
                                   |
                                   v
                            TCA9548A mux
                                   |
                             400 kHz I2C
                                   |
                                   v
                         XIAO nRF52840 Plus
                                   |
                    COBS + protocol v2 over USB
                                   |
                                   v
                              Linux host
                       recorder -> decoder -> uinput
```

The design deliberately uses the plain XIAO nRF52840 Plus, not the Sense Plus.
The plain board has no built-in IMU [H2]. Six identical external IMUs keep the
sensor type, bus path, configuration, and timing evidence comparable. An
onboard Sense IMU would create a seventh, differently routed sensor and does not
replace the dorsal external channel.

The exact Rev-A connector, wire, fanout, mount, assembly, axis-map, and
bring-up contract is frozen in the
[Rev-A one-hand assembly baseline](rev-a-assembly-baseline.md). That artifact
separates source facts, build choices, and hardware gates. None of its physical
gates has run.

### Why this is the first build

- **Source-verified:** XIAO nRF52840 Plus exposes 20 multifunctional pins, native
  USB, an nRF52840 MCU, and a 21 x 17.8 mm wearable-oriented board [H1][H2].
- **Source-verified:** the LSM6DS3TR-C breakout exposes I2C, SPI, INT1, and INT2;
  supports 208 Hz in normal or high-performance mode; and costs USD 9.95 [H4-H6].
- **Source-verified:** the TCA9548A supplies eight selectable bidirectional I2C
  branches at 100 or 400 kHz; deselected branches are disconnected, not
  galvanically isolated [H7][H8].
- **Statically verified:** the standard edge pins provide I2C, six direct
  pulsed data-ready inputs, D9/P1.14 as a Gate 0A cache-commit marker, and
  D8/P1.13 as the later aggregate-snapshot marker. Rev A does not use a
  controller-driven mux reset.
- **Statically verified:** the corrected direct-register path uses at least 207
  I2C clocks per sensor sample with one status poll. Six sensors at 208 Hz
  therefore consume at least 64.584 percent of a 400 kHz bus before start/stop timing,
  scheduling, capacitance, and USB work.
- **Hardware-dependent:** interrupt collisions, branch capacitance, breakout
  level shifters, controller scheduling, noise, and sustained delivery remain
  unmeasured.

This is close to LapCal's inexpensive per-hand mux topology and is designed to
address its reported scan-rate and timing problems. Improvement remains
unverified until Gate 0A passes. The canonical implementation follows the
documented independent-implementation/no-artifact-reuse policy; no LapCal
source, PCB, CAD, data, or model enters it. This document does not claim a
legally established clean-room process.

Leave every breakout's AD0 address jumper open. Each branch connects VIN, GND,
SCL, SDA, and INT1. SCL/SDA pass through the selected mux channel; INT1 bypasses
the mux and returns directly to its dedicated controller GPIO.

Those five signals are not a contiguous five-hole group on the sensor board.
The primary Eagle schematic assigns them to JP1 pins 1, 3, 4, 5, and 8 [H14].
Rev A solders five individual color-coded wires to the labeled sensor holes,
anchors the bundle to the carrier, and terminates the fanout end in a Molex SL
0050579405 housing. That housing mates with a 0705430004 shrouded header on the
fanout. It does not mount directly to the IMU breakout.

Do not daisy-chain the six breakouts through their STEMMA connectors. That
would place identical addresses on one channel and route a long shared bus.

- Use red VIN, black GND, yellow SCL, blue SDA, and white INT1 26 AWG stranded

## Static timing and bandwidth budget

### I2C transaction

The selected driver does four transaction groups after each accelerometer
data-ready edge: mux write, mux readback, one to twenty `STATUS_REG` reads,
then a 12-byte motion burst from `OUTX_L_G` 0x22. The mux path also waits
10 us after every channel select. Gate 0A must retain the observed status-poll
distribution because one extra poll on every read consumes another 11.232
percentage points of the bus.

The minimum one-poll read costs:

```text
mux write                    18 clocks
mux readback                 18 clocks
STATUS_REG register read     36 clocks
12-byte burst from 0x22     135 clocks
total                        207 clocks
```

For `N` status polls:

```text
clocks/read = 171 + 36N
```

At six sensors, 208 samples/s, and one poll:

```text
207 * 6 * 208 = 258,336 clocks/s
258,336 / 400,000 = 64.584 percent minimum bus use
```

This is a lower-bound wire-clock budget. Start/stop timing, mux propagation,
clock stretching, branch capacitance, the 10 us mux settle, status-poll
delays, driver scheduling, interrupt service, and USB work consume the
remaining margin.

If all six interrupts arrive together, the one-poll minimum takes:

```text
6 * 207 / 400,000 = 3.105 ms wire time
+ 6 * 10 us mux settle = 3.165 ms minimum
```

One 208 Hz period is about 4.808 ms, so the minimum leaves about 1.643 ms for
every uncounted cost. An average of two polls consumes 75.816 percent and a
six-way collision takes about 3.765 ms including settle and retry delays. An
average of three consumes 87.048 percent and about 4.365 ms. An average of four
consumes 98.280 percent and about 4.965 ms, already longer than one sensor
period. The 20-poll bound is about 14.565 ms. This topology is worth one
measured trial, but its collision margin still depends on the observed poll
distribution.

### USB stream

Protocol v2 uses 160 raw bytes and at most 162 COBS-delimited bytes per frame.

```text
one hand: 162 * 200 = 32,400 bytes/s maximum
two hands: 64,800 bytes/s maximum
```

The controller uses native USB, not a UART baud-rate bridge. The 60-minute Gate
0 run must still measure delivered records, host scheduling, malformed records,
and transaction latency. Reconnect behavior belongs to Gate 0S.

### Asynchronous sensor clocks

The six IMUs have independent sample clocks. At 208 Hz their latest samples can
legitimately span almost 4.81 ms. The design therefore:

- uses the approximately 75 us pulsed data-ready mode so each observable
  conversion creates a new rising edge;
- timestamps every observed accelerometer data-ready edge in controller time;
- reads and caches that sensor immediately;
- atomically selects the newest completed reading for all six sensors on the
  independent 200 Hz aggregate grid;
- records each selected edge time in the aggregate frame;
- rejects an aggregate above the provisional 5 ms spread ceiling; and
- retains timing offsets for later resampling or ablation.

Because 208 Hz produces eight more readings per second per sensor than the
200 Hz output consumes, a newer completed read intentionally replaces an older
unselected cache entry. At nominal rates that is 28,800 decimated reads per
sensor-hour or 172,800 per hand-hour. Expected replacement is not an
acquisition fault. A pending-read collision, read failure, missing fresh sample,
deadline miss, invalid offset, or USB-slot failure is.

Rev A uses D9/P1.14 as a Gate 0A cache-commit marker and D8/P1.13 as the later
aggregate-snapshot marker. After I2C completes, the worker locks the cache and
then the sensor state, raises D9, stores and latches one slot, holds D9 high for
at least 2 us, attempts D9 low, and only then clears the pending state while
the sensor-state lock remains held. A successful D9 falling edge is the cache
eligibility boundary. A same-sensor physical INT1 before that fall invalidates
the Gate 0A capture; no smaller timing allowance is assumed.

At each independent 200 Hz boundary, the main path locks the same cache, raises
D8, copies and consumes all six latest slots, holds D8 high for at least 2 us,
lowers D8, and unlocks. D8 rising is the selection boundary. The copied array
is immutable during encoding, and D8 never overlaps D9. A logic analyzer
observes both markers, all six INT1 pulses, and I2C transactions directly. The
markers expose commit and selection order; they do not synchronize the sensors
or prove host delivery time. USB and host-kernel backlog can delay receipt
after D8, while the trace observes neither DTR nor the kernel read boundary.
The LSM6DS3TR-C DEN feature can stamp data, but the inspected datasheet does not
prove that fanning out DEN makes six internal samplers simultaneous. Adding a
DEN fanout creates a new measured wiring and manifest revision.

The v0 offset refers to the accelerometer data-ready edge. The gyro registers
are read in the same coherent burst, but they do not have an independent edge
timestamp in this wiring. Requiring both `STATUS.XLDA` and `STATUS.GDA` prevents
silently reusing a consumed value; it does not prove that the two internal
conversions are simultaneous. Gate 0A must measure or ablate that within-sensor
phase. If it matters, move the same sensor to a characterized FIFO read path or
record separate interrupt evidence before changing the decoder claim.

### Initial register configuration

For each mux channel, the board adapter performs this source-derived sequence:

| Step | Register | Value | Reason |
| ---: | --- | ---: | --- |
| 1 | `CTRL3_C` 0x12 | 0x01 | Software reset; poll until bit 0 clears |
| 2 | `WHO_AM_I` 0x0F | expect 0x6A | Reject missing or wrong sensor |
| 3 | `CTRL3_C` 0x12 | 0x44 | Block data update plus address auto-increment, little endian |
| 4 | `CTRL1_XL` 0x10 | 0x58 | 208 Hz, high-performance default, +/-4 g |
| 5 | `CTRL2_G` 0x11 | 0x58 | 208 Hz, high-performance default, +/-1000 dps |
| 6 | `DRDY_PULSE_CFG_G` 0x0B | 0x80 | Approximately 75 us pulsed data-ready |
| 7 | `INT1_CTRL` 0x0D | 0x00 | Keep INT1 quiet until every GPIO callback is installed |
| 8 | read back 0x12, 0x10, 0x11, 0x0B, and 0x0D after each write | expect each configured value | Detect write, register, or channel failure |

After all six quiet profiles pass, install the callbacks and run one bank-arm
operation on the sensor work queue. It selects and verifies each channel,
writes `INT1_CTRL=0x01`, and reads it back before proceeding. Acquisition work
queued by an enabled sensor cannot interleave with these arming transfers.
The [startup admission contract](../../firmware/zephyr/README.md#startup-admission)
defines the observable per-sensor boundary and bounded clean-cache priming
before the first aggregate.

These values follow the ST register tables [H6]. They are a bring-up
configuration, not a tuned signal choice. The first physical captures must
check saturation, noise, aliasing, and whether +/-4 g and +/-1000 dps retain
contact impulses. Change ranges only as a new manifest and rerun Gate 0A.

### Interrupt and read path

The board adapter owns six per-sensor caches:

```text
on INT1 rising for sensor i:
    edge_time = monotonic_controller_us()
    if sensor i already has a pending read:
        increment software_overrun_count
        mark acquisition_overrun
        return
    queue sensor i with edge_time

worker for queued sensor i:
    write exactly (1 << i) to the mux control register
    wait 10 us and read back the mux control register
    require readback == (1 << i)
    read STATUS_REG at 0x1E one to twenty times
    stop when STATUS.GDA and STATUS.XLDA are both set
    read 12 bytes from 0x22
    parse gyro then accelerometer as signed little-endian i16
    acquire the shared sample-cache lock
    acquire sensor i state lock
    raise D9
    store and latch the reading with the captured edge_time
    hold D9 high for at least 2 us
    require a successful D9 falling edge as the cache-eligibility boundary
    if a prior completed reading was never selected, classify its replacement
        as expected latest-sample decimation, not acquisition overrun
    clear pending flag while sensor i state remains locked
    release sensor i state lock
    release the shared sample-cache lock
```

If a physical INT1 edge for sensor `i` occurs before that D9 fall, the Gate 0A
capture is invalid. The implementation does not claim a shorter tolerance.

At each 200 Hz aggregate boundary, main acquires the sample-cache lock, raises
D8, copies and consumes all six latest slots, holds D8 high for at least 2 us,
lowers D8, and unlocks. The D8 rising edge is the aggregate eligibility
boundary. Because D9 uses the same lock, the latest successful D9 falling edge
before D8 identifies the newest read eligible for that sensor. The copied
six-sample array is immutable during encoding. `read_latest` returns that copy
and each exact source-edge timestamp. A stale, missing, or unexpectedly
overrun sample still produces an evidence frame with validity/flags set. Any
marker write failure latches an acquisition fault and fails the analyzer
trace.

Before sensor I/O or interrupt enable, boot emits the fail-closed analyzer
anchor `D8 high >=20 us, both low >=20 us, D9 high >=20 us, both low >=20 us` while
both normal marker paths are unavailable. Normal D8 and D9 pulses each include
at least a 2 us high hold. The analyzer must be armed before controller reset or
power-on and must see the complete anchor as the first non-idle activity. The
first later D8 snapshot has ordinal 0 and produces frame sequence 0; normal D8
ordinal N therefore maps to frame sequence N even when the host begins
receiving after pre-roll frames were dropped. Marker width alone never creates
an anchor. The aggregate timer and sequence advance even when DTR is absent.
Reconnect never resets either. The host does not monitor DTR as a fault signal.
A host-visible source disconnect or transport fault terminally revokes live
output, while Gate 0A does not treat DTR as a delivery witness.

The FIFO stays in reset-default bypass mode. `FIFO_STATUS2.OVER_RUN` is a FIFO
overrun signal, not a direct-output loss counter, so Rev A neither reads nor
reports it. Pulsed INT1 plus analyzer accounting can expose observed conversions
and software capacity faults, but the direct-register protocol alone cannot
prove that every internal conversion produced a captured pulse.

The GPIO edge path must timestamp and enqueue only; it must not perform I2C in
interrupt context. Prefer nRF52840 GPIO-event-to-timer hardware capture when
the selected SDK exposes a bounded implementation. An ISR timestamp is
acceptable only if the six-edge collision test measures its error against the
logic analyzer and it remains inside the manifest limit under USB and I2C load.

The aggregator then:

1. assigns the exact per-hand sequence before any USB enqueue attempt;
2. uses the scheduled 5,000 us grid time as aggregate time;
3. writes each signed sample-time offset;
4. encodes the fixed 160-byte frame and CRC;
5. COBS-encodes it into a bounded 162-byte buffer;
6. attempts to enqueue it to native USB;
7. on enqueue failure, discards that frame and latches acquisition-overrun onto
   the next accepted frame; and
8. uses the sequence gap plus that flag or a retained malformed transport
   candidate as the canonical host-visible fault accounting.

There is no second diagnostic protocol in v0. Rev A has no readable queue-depth
or drop-counter telemetry. Gate 0A derives loss from the sequence and retained
transport evidence. The fixed six work items, one pending bit and cache per
sensor, and ordered terminal transport prove bounded storage by construction;
analyzer timing proves whether that bounded design keeps up.

Ordinary acquisition emits only SensorFrame v2. The same COBS byte stream
admits `IKQ2` and `IKR2` only inside the Gate 0A quiescing recorder. Calibration,
neutral, replay, ordinary recording, and live consumers reject either control
record. No received controller record can emit an OS key.

### Board adapter tests before wearing it

- All six `WHO_AM_I` reads pass only on the expected channel.
- Every permanent housing and branch label matches its continuity record and
  mounted photo. Swapping two identical IMU branches cannot be detected from
  `WHO_AM_I` or the static manifest, so any disconnect or swap requires a new
  inspected continuity record, mount ID, photo hashes, and six-face axis map.
- Each INT1 line toggles the expected GPIO and sensor index.
- The DSLogic Plus records raw bits 0 through 5 for all six INT1 lines, bit 6
  for D8, bit 7 for D9, bit 8 for SDA, and bit 9 for SCL. The native trace
  derives mux select, burst length, read order, cache eligibility, snapshot
  order, and worst interrupt collision.
- Arm the analyzer before a full sensor/controller power cycle, or a controller
  reset after verified sensor quiescence. Require the exact four-phase boot
  anchor before any INT1 or I2C activity, then the validated quiet configuration
  and arming sequence. Each normal D8 ordinal maps to the equal frame sequence.
- Holding one interrupt line or disconnecting one branch produces invalid
  evidence without stalling the other five.
- Whole-board power cycling after a mux fault creates a new boot identity and
  recovers, or the adapter produces a declared fatal state.
- Sequence and controller time never reset without a new boot/session identity.
- USB unplug, host backpressure, and controller reset produce bounded COBS
  recovery and all-up host output.

The service asks for a three-second neutral hold and regular-keyboard examples

least 60 seconds per hand of measured motion-rich, non-contact, non-saturated
ordinary-motion windows. Quiet rest, contact-like motion, saturation, and
caller-supplied duration do not count.

Each passive target first shows a preparation instruction. At the plan cue,
the page shows a distinct `Tap ... now.` instruction. The service records no
response until the visible browser acknowledges that exact rendered-state
revision after two animation frames. The accepted acknowledgment opens a
provisional 1.5-second response gate; it is not contact truth. The retained
target segment is 1.8 seconds. A causal sensor trigger, frozen before passive
fitting, inspects both hands and accepts exactly one contact only when its hand
and finger match the prompt. No contact, wrong hand, wrong finger, and multiple
contact are explicit rejected outcomes. The screen-only 34-position physical
grid highlights the intended position; it adds no mark or sensor to the typing
surface. A missing receipt fails closed.

which sensor records it kept. It does not attest that a human saw the cue, that
the wearable was mounted as declared, or that a physical contact occurred as
prompted. A hardware study still needs an honest operator and independent truth

### Live shutdown and evidence finalization

Treat output neutralization and evidence finalization as different milestones.
On SIGINT, SIGTERM, source loss, clock failure, decoder failure, or output
failure, the output owner attempts all-up before reader coordination, footer
sync, or offline fitting. The 250 ms Gate 0S value applies to independent evdev
observation of that all-up transition. It does not bound the later session and
report work.

The reader mailbox closes atomically at the first terminal cause. Chunks already
admitted are drained to the session as evidence only. Reader-local or later
chunks are rejected. The resulting session must be one exact gap-free prefix;
a FIFO writer's successful return is not proof that the mailbox admitted that
chunk. A late signal cannot replace an earlier transport or output fault.
The retained prefix includes the chunk that triggered operational rejection,
merge-held candidates, and parser-held suffixes exactly once. Terminal evidence
uses the same per-source decoder but does not apply operational receipt,
lateness, or pending-capacity admission gates. Within-source byte order and the
original completion receipt timestamps remain intact, including regressed
timestamps; an unterminated suffix retains its last byte-chunk receipt, not the
later synthetic disconnect time. Admission closes before any evidence sink I/O.
Evidence-retention or finalization failures are attached to the first cause,
never substituted for it, and no terminal evidence reaches output or rearming.
A failure to retain admitted evidence leaves the session without `END3`, even
if later sink writes would succeed. It cannot publish a durable bundle.

Durable success requires all of the following on Unix:

1. write the `END3` footer;
2. sync the session file and parent directory;
3. strictly audit and hash the complete session while fitting exact clock
   statistics with bounded memory;
4. write a live-clock-report-v2 document whose manifest and session hashes
   match those exact bytes; and
5. sync the report file and parent directory before publishing terminal status.

`END3` is necessary but not sufficient. A post-footer session sync or strict
audit I/O failure can leave footer bytes in an unpublished partial. Durable
success requires the complete sequence above and successful publication; the
footer alone is not an oracle.

There is no universal two-second or other wall-clock completion promise for
these steps. A closed or blocked status consumer cannot erase the bundle. Run
the permanent Linux syscall oracle explicitly on a Crabbox:

```text
box exec --cwd invisible_keyboard BOX_ID bazelisk --batch test //:live-durability-syscall-test --nocache_test_results --test_output=all
```

The oracle traces two real recording-mode CLI shutdowns. It is not a storage
hardware power-loss test and does not establish macOS or Windows durability.

## Guided calibration and training

The user wears the hardware and first types project-supplied text on a normal
keyboard. Linux key events provide labels for a bounded signal precheck. The
app learns the neutral pose and verifies source alignment; the user does not
enter keyboard angle or switch travel. Keyboard evidence cannot admit a model.

The physical keyboard cannot validate desk tapping, so setup then moves the
keyboard away and collects a short prompted passive-surface block. The initial
plan is:

1. 5-second full-sensor health check.
2. 3-second neutral hand pose.
3. Normal-keyboard prompts selected by `count_shortfall +
   separated_block_shortfall` until the non-admission precheck completes for
   the 29 keyboard-addressable positions. `B`, Space, Backspace, and both outer
   thumbs stay passive-only.
4. Freeze the causal collection trigger after the non-admission signal precheck.
5. Collect three accepted passive-surface centroid taps for all 34 physical
   positions, plus a disjoint ten-target passive threshold block.
6. Lock the artifact and final decoder threshold, then run held-out passive
   validation with at least 60 seconds per hand of measured motion-rich,
   non-contact, non-saturated ordinary-motion windows.
7. Persist `CalibrationPhase::ValidationPassed` and
   `CalibrationSnapshot.heldout_validation_passed=true` only if enabled keys
   pass, all reserved positions abstain, and final output is neutral.
8. Require a fresh per-process no-movement user attestation before live output.

The UI exposes coverage, validation, and hardware health separately. It has a

The first frozen plan has 214 prompted passive contacts plus 132 seconds of

## Stage gates

### Gate 0A: one-hand electrical stream integrity

Run one complete hand for at least 60 minutes at the selected settings. At 200
aggregate frames/s this schedules at least 720,000 frames. The supervising
wrapper keeps the analyzer open for exactly 3,610 seconds, issues quiescence in
the raw-size window at 3,604 seconds, and requires at least five seconds of
analyzer-idle tail after the terminal marker. The host then observes another
100 ms of TTY silence before finalizing IKS3.

The decisive analyzer artifact is the capture guide's DSLogic Plus raw stream:
ten bits, 2 MHz, 7,220,000,000 words, 14,440,000,000 bytes, and at least 3,601
scored seconds. Short preflight or soak captures cannot substitute for it.

Go only when:

- every sequence number is accounted for;
- valid receipt is at least 99.9 percent;
- there is no silent corruption, reset, duplicate, or reorder to the model;
- every sequence gap is explained by acquisition-overrun on the recovered
  frame or a retained malformed transport candidate;
- per-sensor ODR, jitter, and timestamp offsets are reported;
- the machine-generated sidecar binds the exact 14.44 GB native raw capture,
  capture executable, patch, firmware bytes, and settings; the score binds that
  raw artifact to the exact manifest and session;
- IKS3 contains exactly one outbound `IKQ2` request and one matching inbound
  `IKR2` receipt, with no post-receipt bytes, and clean SensorFrame `N`
  immediately precedes the receipt whose final sequence equals `N`;
- host request-to-receipt time is at most 750 ms, the clean final scheduled
  boundary occurs within 400 ms of firmware request acceptance, and firmware
  offers the receipt within 500 ms of acceptance;
- the raw capture includes one valid four-phase D8/D9 boot anchor before sensor
  activity, the complete validated quiet configuration and per-sensor arming
  sequence, and bounded first-sample priming. Normal D8 snapshot ordinal N maps
  to frame sequence N;
- the full-capture analyzer accounting reports pre-admission startup pulses
  separately from admitted pulsed-INT1 edges, observed ODR, interval jitter,
  selected reads, decimated reads, the 250 us decimation-phase histogram, and
  selected-read age;
- every admitted edge and completed motion read is accounted for exactly once,
  with no unexplained edge, read, duplicate ordinal, reuse, or selection error.
  Pre-first-snapshot replacements are decimation without a phase grid;
  pre-grid and phase-histogram counts together equal total decimation;
- every well-formed motion read has one unambiguous D9 cache-commit pulse after
  its I2C completion, its successful D9 fall is its eligibility boundary, and
  every aggregate has one later D8 snapshot pulse whose rise is the selection
  boundary;
- no same-sensor physical INT1 occurs between a read's store and successful D9
  fall;
- every normal D8 and D9 high interval is at least 2 us and less than 20 us,
  and the two marker intervals never overlap;
- every aggregate links six unique INT1 edges and read ordinals, correct mux
  select/readback, the exact register sequence, 1 to 20 status polls, and raw
  motion payloads that uniquely match the linked host frame;
- for every selected sensor, the read is the newest completed eligible read
  whose D9 falling edge precedes the D8 rising edge, and it is linked to exactly
  one host frame;
- the copied six-sample array remains immutable after D8 rise while the frame
  is encoded;
- at least one observation has all six reads pending at once;
- every read completes before that sensor's next observed INT1 edge;
- the observed status-poll histogram and maximum INT1-to-read-complete latency
  are reported;
- inter-sensor spread stays within 5 ms or the decoder explicitly time-aligns
  the samples and passes an ablation;
- the analyzer decoder reports no unmatched edge, unclassified I2C read,
  nonlatest selection, or decode error;
- final D8 `N` is the only admission cutoff, no normal D9 or acquisition I2C is
  legal after its rise, and every pre-cut INT1 edge satisfies ordinary
  acquisition accounting;
- after final D8 falls, the analyzer decodes exactly 52 ordered shutdown
  transactions and exactly 1,422 SCL rises with every readback and ACK valid;
- the stop marker changes D8 and D9 in the same analyzer sample, has a width of
  200 through 400 samples, appears exactly once, and has no intermediate
  one-pin state; and
- every later raw word is idle `0x0300` for at least 10,000,000 samples, while
  the recorder remains silent through analyzer EOF plus 100 ms before `END3`.

The source timer and sequence advance without DTR, and reconnect never resets
them. The host does not monitor DTR as a fault signal. A host-visible source
disconnect or transport fault still revokes live output, but the analyzer must
not call D8 a host-delivery marker. It cannot observe USB or host-kernel
backlog, DTR, or the kernel read boundary. Host receipt and sequence accounting
remain separate session evidence.

Stop on any silent loss, timestamp ambiguity, wrong channel identity, payload
ambiguity, physical same-sensor edge before D9 eligibility, read that crosses
the next same-sensor edge, or four-poll average that overruns the 208 Hz period.
Expected 208-to-200 latest-sample decimation is not a stop condition when every
read is classified and selection is newest-at-snapshot. Gate 0A does not
authorize OS output.

### Gate 0S: host and output safety

Gate 0S is separate because Rev A's analyzer cannot observe application key
state. Run its native portion on Linux with required, non-skipping `uinput`
access. Repeat the controller-fault portion after both physical hands exist.

Go only when:

- 10,000 Core-28 down/up pairs traverse the kernel event device with exact
  order and zero stuck keys;
- injected receipt regression, host-clock regression, merge lateness, pending
  overflow, output failure, and either-hand silence all terminally revoke the
  live instance and produce an observed all-up state within 250 ms;
- USB disconnect, controller reset, and reconnect cannot splice identities or
  epochs into the old run; a new run starts neutral with a new boot/session
  identity;
- every live process requires a fresh explicit no-movement user attestation,
  and every source, watchdog, identity, clock, output, or process fault
  terminally revokes it without rearm;
- normal stop and SIGTERM finalize the session and terminal report; and
- SIGKILL destroys the owned virtual device and the next process starts
  neutral. Do not claim an application-observed 250 ms all-up event after
  SIGKILL because the process cannot emit one.

Any stuck key, unfinalized recoverable fault, identity splice, bypass around
held-out validation, or reused live attestation fails Gate 0S.

### Gate 0B: observable contact

One-hand contact work remains a useful non-armable engineering pilot. The
canonical Gate 0B disposition requires both hands, an already frozen contact
detector, independent contact truth, at least five held-out participants, two
real remounts per participant, and at least 50 intentional taps per finger,

latency, extra contact event, or negative false activation is a zero-tolerance
failure. A favorable point whose one-sided participant-bootstrap boundary

difference has no repeatable contact evidence.

Use participant-disjoint train, validation, and held-out splits. Freeze the

macro-F1 at least 90% across the 28 enabled outputs, p95/p99 latency at most
100/200 ms, no anticipatory event, zero extra outputs, and zero enabled outputs
on the six reserved positions. Both each point and its confidence boundary
must clear the threshold. The full null-inclusive confusion matrix remains a

confidence boundary did not clear. Do not reinterpret either result or add
more rows to an inspected frozen round.

after stream, mount, and time-alignment quality pass. A dictionary or phrase
model may define a separate transcription product, but it cannot repair this

## Stress matrix

| Layer | Stress | Required observable result |
| --- | --- | --- |
| Frame codec | every truncated length, extra byte, bad magic/version/hand/count/mask/flag/CRC | exact rejection, no parser shift |
| COBS stream | arbitrary chunks, inserted byte, dropped byte, oversized candidate, missing delimiter | bounded memory and recovery at next zero delimiter |
| Acquisition | all interrupt collisions, stale cache, wrong mux channel, unplugged sensor, late read | explicit invalid/overrun evidence, other channels continue |
| Timing | controller wrap, restart, per-sensor regression, 5 ms spread boundary, host clock drift | new session or explicit rejection; never silent repair |
| Session | duplicates, gaps, reorder, invalid records, crash before finish | append-only replay and exact accounting |
| Calibration | missing class, bad sensor, no/wrong/multiple hand or finger contact, keyboard-only pass/surface fail | no passed validation artifact and one named cause |
| Decoder | noise, remount, shared motion, packet loss, simultaneous taps, reserved positions | correct result or abstention; no guessed key on fault |
| Pipeline | long idle, two separated taps, held contact, bounce-like repeated impulse | one decision per qualified tap and causal bounded delay |
| Output | 10,000 tap pairs, duplicate down, orphan up, time regression, disconnect, adapter error | exact kernel events and zero stuck keys |
| End to end | controller unplug during press, source/decoder/output fault, planned stop, host sleep, focus change | all-up within 250 ms and explicit recovery evidence |
| Uncatchable exit | SIGKILL while one key is down, then process restart | owned `uinput` device disappears, the observer sees no stuck key, and the next process starts neutral; record elapsed observation but make no 250 ms claim |

Synthetic tests exercise the software shape. Physical fault injection must rerun
the same matrix on the full topology.

## Decision tree and fallback paths

### Keep the selected I2C topology when

- Gate 0A passes with useful margin;
- all six sample offsets remain observable;
- no branch has persistent signal-integrity faults; and
- the breakout mount does not dominate the signal.

### Switch the same LSM6DS3TR-C boards to shared SPI when

- 400 kHz I2C utilization or collision latency causes overrun;
- mux selection or level shifting causes measurable jitter/errors; or
- a higher sensor ODR becomes necessary.

The ST datasheet specifies SPI operation up to 10 MHz [H6], but Rev A does not
have enough frozen standard-edge GPIO for six chip-selects plus six data-ready
lines. A shared-SPI trial is therefore a new controller/harness revision, not a
rewire promised by this build. Select its extra GPIO only after official pin
mapping, continuity, a board overlay, and logic-analyzer evidence agree. Rerun
Gate 0A before comparing its signal results with Rev A.

### Build a custom ICM-42688-P sensor board only when

- the LSM6 timing/noise/range is the measured blocker;
- a 24 MHz SPI bus or external clock input addresses that blocker; and
- the team accepts a custom PCB before the final wearable form.

This is not the first build. Current off-the-shelf breakout supply and pin
exposure are less consistent, while a custom board adds layout and assembly
risk before contact/key evidence exists.

### Stop or change the product claim when

- same-finger Core-28 positions fail held-out separation after timing and mount
  quality pass twice;
- ordinary motion cannot meet the false-activation gate without an interaction
  the user did not authorize;
- the required mounts are unsafe or intolerable; or

| Field | Value |
| --- | --- |
| `schema` | `invisible-keyboard-one-hand-pilot-truth-v1` |

| `session_id` | The session header's 16-byte identifier as 32 lowercase hex characters |

| `source` | `high-speed-video`, `contact-switch`, `instrumented-keyboard`, or `optical-tracker` |
| `truth_artifact_sha256`, `clock_mapping_sha256` | Lowercase SHA-256 of the exact two archived files passed to `score-pilot` |

Use each negative kind exactly once: `mouse-use`, `phone-handling`, `scratching`,
`gesturing`, `object-handling`, `hand-repositioning`, and `quiet-rest`.
`neutral.start_us` equals the first recorded frame time; `neutral.end_us` equals

nominal period. Every contact's complete inclusive 200 ms matching window must
fit within observation. The typed definition is [`PilotTruth`](../../src/pilot.rs).

#### Frozen signal and purchase rule

Run continuous causal 16-frame windows over the measured axis-normalized
samples. For each finger, the corrected energy is the maximum squared change
from the oldest window frame after dorsal subtraction. The raw ablation uses
the same windows without dorsal subtraction. Neither variant reads contact
labels when deriving thresholds or detecting events.

For each variant and finger, derive thresholds from initial neutral only:
`low = max(1024, 2 * neutral_max)` and
`high = max(4096, 8 * neutral_max)`. Two consecutive high windows with the
strongest finger at least 1.5 times the second strongest emit one event at the
second window's time. Four consecutive all-low windows rearm the detector.
Do not reset it at truth or negative-interval boundaries. Match events to
truth one-to-one in the inclusive interval from contact time through 200 ms
later. Early or unmatched events count as extras; wrong-finger matches fail.
Wrong-finger events also count as extras. A missing contact has neither a
correct nor a wrong-finger event in its matching window.

The report records both variants, per-finger signal/noise and saturation,
misses, wrong fingers, extra events, and per-position recall. Its
`supports-two-hand-build` result requires complete coverage, no bad or
saturated frames, no extra events, at least 90 percent correctly matched
contacts overall, at least 80 percent recall for every physical position, and
a median corrected signal/noise energy ratio of at least four for every
finger. Otherwise its result is `stop`. These thresholds are provisional
engineering choices, not hardware-validated performance guarantees.
Only corrected outcomes decide support; raw outcomes remain an ablation.
For each finger, signal/noise is the median peak energy in its independent
contact windows divided by `max(1, neutral_max_energy)`. Sequence loss,
duplicate or reordered frames, time regressions, and gaps over two nominal
periods reject the attempt. Invalid samples, acquisition flags, excessive
within-frame skew, or saturation cannot produce support.

Buy the second rig only if all nine frozen attempts support that limited
decision and their physical safety records pass. A failed attempt ends this
round; revise the physical design and preregister a new round rather than
rerunning until it passes. Retain raw-ablation failures as well as corrected
results. No pilot report is a calibration artifact, live-output permission,
Gate 0B pass, or evidence of exact within-finger key separability.
