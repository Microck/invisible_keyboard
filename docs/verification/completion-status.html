Invisible keyboard: what is done and what is left

The hardware-independent software is complete and verified. A working physical keyboard is still unproved. The next step is to build and measure one wired hand, then decide whether its sensor signals justify continuing.

These checks establish software behavior under the recorded conditions. They do not establish useful sensor signals, real cue perception, typing accuracy, comfort or safe wear. No physical controller, IMU, analyzer or wearable was attached or flashed.

Execution limits and process disclosure

The full x86-emulated capture run missed the unchanged 10 ms polling limit. The timing-sensitive cases then passed natively in the same Crabbox. Binary identity and loadability checks stayed on x86. No production code or assertion changed to make this partition pass.

The browser run included synthetic fault injection. Its proxy rewrote Origin, so it does not prove direct Origin rejection, pixel paint, occlusion or physical sensor truth. Successful process-kill cleanup also does not establish a 250 ms all-up guarantee for SIGKILL.

One reviewer ran a host-side manifest comparison against the sandbox-only rule. That result was withdrawn and excluded. The accepted source comparisons ran inside Crabbox.

Remaining work

The open work requires real parts, measurements and human use. Those experiments may require firmware, decoder or hardware changes. Passing the software checks does not guarantee that the sensing approach will work.

  1. Qualify the parts and assemble the wired rig

    Check the exact boards, wiring, power envelope, thermal behavior and wear conditions against the assembly contract. Keep PWR_LINK open until the specified checks permit connection.

    Required evidence: accepted parts, harness and power/wear measurements for Gates A, B and E.

  2. Measure the actual acquisition path

    Flash and read back the controllers, then measure sensor registers, interrupt edges, I2C, USB delivery, capture markers, quiesce and idle-tail behavior. Run the sustained analyzer capture.

    Required evidence: a physical Gate 0A capture that satisfies the timing and integrity contract.

  3. Commission the sensor axes and run the pilot

    Record real six-face axis poses and complete the finite nine-attempt one-hand pilot. A failure is a stop decision, not permission to relabel or relax the evidence.

    Required evidence: bound axis characterization and an admissible pilot result from the actual rig.

  4. Prove that the positions are distinguishable

    Measure contact and acting-finger detection, then test all 34 positions with the 28-output policy. Hold out data for validation. Test remounts, surfaces, people and ordinary movement without treating training performance as proof.

    The central unresolved question is whether several keys assigned to the same finger remain distinguishable after remounting and during ordinary motion.

  5. Prove usable and safe typing

    Test real application focus, input methods, suspend and disconnect behavior. Then measure live text entry, speed, error rate, comfort and safety.

    Required evidence: the real-host gate and physical use-study gates. Kernel event tests alone do not establish these outcomes.

The next concrete step

Build the one-hand wired measurement rig in the first-build roadmap:

  • One Seeed Studio XIAO nRF52840 Plus controller.
  • One Adafruit TCA9548A I2C multiplexer.
  • Six identical Adafruit LSM6DS3TR-C IMU breakouts.
  • One IMU per finger and one on the back of the hand, with six direct data-ready lines.

Complete parts and power qualification before connecting the gated power link, then follow bring-up, axis commissioning and the finite pilot. Defer BLE, batteries, custom PCBs and a consumer enclosure until the physical evidence supports continuing.
